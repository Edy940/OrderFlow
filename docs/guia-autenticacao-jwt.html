1. Subir a API

1Abra o terminal na pasta do projeto e rode:
cd src\OrderFlow.Api
dotnet run

A API sobe em duas URLs (perfil https, o padrão):

ProtocoloURL
HTTPShttps://localhost:7225
HTTPhttp://localhost:5186

Swagger fica em: https://localhost:7225/swagger

2. Registrar um usuário

Só precisa fazer isso uma vez por usuário. Se já tem um usuário criado, pule para o passo 3.

Endpoint: POST /api/v1/auth/registrar

Corpo da requisição:

{
  "nome": "Seu Nome",
  "email": "teste@teste.com",
  "senha": "SenhaForte123"
}
Regras da senha (obrigatórias): mínimo 8 caracteres, pelo menos 1 letra maiúscula, 1 minúscula e 1 número. Ex: SenhaForte123 é válida.

3. Fazer login e obter os tokens

Endpoint: POST /api/v1/auth/login

Corpo da requisição:

{
  "email": "teste@teste.com",
  "senha": "SenhaForte123"
}

Resposta (200 OK):

{
  "accessToken": "eyJhbGciOi...",
  "accessTokenExpiraEm": "2026-08-24T15:20:00Z",
  "refreshToken": "a1b2c3d4-...",
  "refreshTokenExpiraEm": "2026-08-31T15:05:00Z"
}
Tempos de validade (fixos no código): Access Token dura 15 minutos. Refresh Token dura 7 dias.

4. Usar o Access Token nas requisições

Em toda chamada a um endpoint protegido (ex: POST /api/v1/clientes), envie o token no header Authorization:

Authorization: Bearer eyJhbGciOi...

Se o token expirou (depois de 15 min), a API responde 401 Unauthorized — nesse caso, vá para o passo 5.

5. Renovar o token quando expirar (Refresh Token)

Não precisa logar de novo — use o refreshToken que você guardou no login para pedir um novo par de tokens.

Endpoint: POST /api/v1/auth/refresh

{
  "refreshToken": "a1b2c3d4-..."
}

Resposta: um novo accessToken (mais 15 min) e um novo refreshToken (o antigo é invalidado). Sempre guarde o novo refresh token da resposta.

O refresh token só funciona enquanto estiver dentro dos 7 dias de validade e não tiver sido revogado. Depois disso, é preciso logar de novo (passo 3).

6. Revogar um token (logout)

Endpoint: POST /api/v1/auth/revogar

{
  "refreshToken": "a1b2c3d4-..."
}

Isso invalida o refresh token — útil para implementar "logout" de verdade.

7. Testando pelo Swagger (mais fácil)

1Abra https://localhost:7225/swagger no navegador.
2Expanda POST /api/v1/auth/login, clique em "Try it out", cole o JSON do passo 3, clique em "Execute".
3Copie o valor de accessToken da resposta (sem aspas).
4No topo da página, clique no botão Authorize (ícone de cadeado).
5Cole o token no campo (digite Bearer antes do token, com espaço) e clique em Authorize, depois Close.
6Agora todos os endpoints protegidos (ex: criar cliente) já enviam o token automaticamente.

8. Testando pelo PowerShell (script completo)

# 1. Registrar (só na primeira vez)
Invoke-RestMethod -Uri "https://localhost:7225/api/v1/auth/registrar" -Method Post `
    -Body (@{ nome = "Seu Nome"; email = "teste@teste.com"; senha = "SenhaForte123" } | ConvertTo-Json) `
    -ContentType "application/json" -SkipCertificateCheck

# 2. Login
$resp = Invoke-RestMethod -Uri "https://localhost:7225/api/v1/auth/login" -Method Post `
    -Body (@{ email = "teste@teste.com"; senha = "SenhaForte123" } | ConvertTo-Json) `
    -ContentType "application/json" -SkipCertificateCheck

$accessToken  = $resp.accessToken
$refreshToken = $resp.refreshToken
Write-Host "Access token expira em:" $resp.accessTokenExpiraEm

# 3. Usar o token em um endpoint protegido
Invoke-RestMethod -Uri "https://localhost:7225/api/v1/clientes" -Method Post `
    -Headers @{ Authorization = "Bearer $accessToken" } `
    -Body (@{ nome = "Cliente Teste"; email = "cliente@teste.com" } | ConvertTo-Json) `
    -ContentType "application/json" -SkipCertificateCheck

# 4. Quando der 401 (token expirou), renove:
$novo = Invoke-RestMethod -Uri "https://localhost:7225/api/v1/auth/refresh" -Method Post `
    -Body (@{ refreshToken = $refreshToken } | ConvertTo-Json) `
    -ContentType "application/json" -SkipCertificateCheck

$accessToken  = $novo.accessToken
$refreshToken = $novo.refreshToken   # guarde o novo refresh token!
